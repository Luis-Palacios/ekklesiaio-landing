# ekklesiaio — landing page

Pre-launch, bilingual (EN/ES) landing page with an email waitlist for ekklesiaio, a small-group reporting SaaS for churches. Production: https://ekklesiaio.com (Vercel; DNS on Cloudflare).

## Read first
- **`docs/DESIGN.md`** is the build spec: stack, structure, behavior, waitlist flow, i18n, build order. Follow it.
- **`docs/design/*.dc.html`** hold the approved design as source. Take exact visual values from them: spacing, sizes, colors, clamp() values, and structure. These files are design references, not app code: don't import them, and don't copy their `{{…}}` template syntax or `DCLogic` scripts.
- **`brand/theme.css`** holds the Tailwind v4 tokens. Use the token utilities (`bg-navy-900`, `text-ink`, `font-display`, `rounded-control`…), not raw hex.
- **`messages/en.json` / `messages/es.json`** hold all copy. Never hard-code user-facing text, and keep both files' keys identical.
- **`AGENTS.md`** (generated by Next.js) points to the version-matched Next.js docs in `node_modules/next/dist/docs/`. Read the relevant guide there before using a Next.js API.

## Ground rules
- TypeScript strict, Server Components by default; add `"use client"` only where needed (waitlist form, Turnstile).
- Check current library docs (Next.js, next-intl, Tailwind v4, Drizzle, Resend, Upstash, Turnstile) before using an API. Don't rely on memory for version-specific details.
- Keep dependencies minimal, and don't add a UI kit or icon library.
- Accessibility is a requirement, not polish: labels, focus states, contrast rules from DESIGN.md §3.1 and §8.
- Never commit secrets. Keep `.env.example` up to date.
- Copy changes: edit both locale files. If a Spanish string is missing, add an English placeholder prefixed `[ES TODO]` and say so in the PR, rather than machine-translating silently.
- Don't invent legal or policy text, prices, dates, or stats. Use the open items list in DESIGN.md §9.

## Decisions and gotchas so far
- **Next 16.4:** the middleware file is `src/proxy.ts` (renamed from `middleware.ts` in Next 16; DESIGN.md §2 predates this). `cacheComponents` and `partialPrefetching` are on (create-next-app defaults).
- **next-intl:** the locale comes from `next/root-params` in `src/i18n/request.ts`, so no `setRequestLocale` calls are needed and `/en`, `/es` stay static. `next/root-params` doesn't work in route handlers, so `opengraph-image.tsx` (step 6) must read the locale from its `params`.
- **Client messages:** the layout's `NextIntlClientProvider` passes `messages={null}`. Give a client component only what it needs: either pass strings as props from a server parent, or wrap it in a provider with just its namespace (e.g. `form`).
- **SEO:** hreflang comes only from `generateMetadata` (`alternates`). next-intl's `Link` header is off (`alternateLinks: false`).
- **Proxy matcher:** it must contain `\\.` (escaped dot) in the TS string. After any change, check the compiled pattern in `.next/server/functions-config-manifest.json`. A lost escape silently stops the proxy from running on every path except `/`.
- **Language names:** "English"/"Español" (autonyms) live in `localeNames` in `src/i18n/routing.ts`, not in the message files.
- **`npm audit`:** 5 "high" findings are one advisory in `braces` (GHSA-vfj7-8cjw-p6xm), reached only through the ESLint config. There's no patched release, and `npm audit --omit=dev` is clean. Don't run `npm audit fix --force`, because it downgrades `eslint-config-next` to 14. Recheck when `braces` ships a fix.
- **Held-back dev tools:** ESLint stays at 9 (the React, jsx-a11y and import plugins don't support 10). TypeScript stays at 5.9 (typescript-eslint needs TS < 6.1).
- **Page structure:** sections live in `src/components/sections/`, and shared eyebrow/h2/container styles in `src/components/typography.tsx`. `line-subtle` (`#EEF0F3`, card dividers) was added to `brand/theme.css`. The sample leader names in `reports-card.tsx` are constants, not message keys.
- **Sticky header offset:** `scroll-padding-top` in `globals.css` steps with the header's wrap points (1 row < 768px, 2 rows 768–859px, 1 row above). Recheck if nav copy changes.
- **Mobile header:** below `md` the section links are hidden, so the header is one row (71px at 360–390px). Below `sm` it shows `LogoMark` (cropped viewBox) instead of the wordmark lockup, and the language switcher drops its decorative globe; the full lockup doesn't fit beside the switcher and CTA at 390px. Write it as plain `@media` CSS: Prettier reorders `@apply` variants, and Tailwind then emits `min-[860px]` before `md`, which breaks the cascade.
- **Build-time env:** `/en` and `/es` are prerendered, so the footer reads `CONTACT_EMAIL` at build time. Without it, the Contact link is omitted.
- **Year:** `new Date()` breaks prerendering under `cacheComponents`. The footer reads it in a `"use cache"` helper with `cacheLife("days")`.
- **Waitlist layout:** the zod schema lives in `src/lib/waitlist-schema.ts` (it's imported by the client form too) and uses `zod/mini` to keep the bundle small. The signup rules are in `src/server/waitlist.ts`. All SQL is in `src/server/waitlist-repo.ts`, so tests mock the repo, not Drizzle. `waitlist-form.tsx` is a server wrapper that passes only `form` messages to `waitlist-form-client.tsx`.
- **Waitlist behavior:** the resend throttle and the unsubscribed → pending move are conditional `UPDATE`s, so concurrent submits can't both send. If a send fails, `confirm_sent_at` is restored so a retry isn't throttled. The action re-sends the typed email in its state, because React resets the form after the action runs.
- **Turnstile:** nothing loads from Cloudflare until the form is first focused, pressed or submitted (`load` prop on `TurnstileWidget`); loading it with the page cost ~15 Lighthouse mobile points, and only the form that's used gets a widget. It's explicitly rendered with `appearance: "interaction-only"` and reset after every result that isn't success (tokens are single-use, 5 min). With JS, the form dispatches the action itself: if the token input is empty on submit, it waits up to 5s (`waitForToken`, resolved by Turnstile's `callback`) with the form shown as busy, then sends whatever it has. Turnstile fills its hidden input before calling `callback`. Without JS, the form posts but has no token, so it gets the error state. The widget is in Invisible mode. Production uses real keys; Preview and local use Cloudflare's always-pass test keys (see `.env.example`). The token is verified server-side with siteverify. When `VERCEL_ENV === "production"`, the returned `hostname` must also equal `getSiteUrl().hostname`; test keys always report `example.com`, so the check is skipped elsewhere. A missing secret fails closed.
- **Rate limit:** Upstash env vars are `KV_REST_API_URL` / `KV_REST_API_TOKEN` (the Vercel integration's names), passed to `new Redis({ url, token })` explicitly. Upstash's docs only document `UPSTASH_REDIS_REST_*` for `Redis.fromEnv()`. If they're missing, the rate limit is skipped outside production and fails closed in production. Not used locally.
- **Privacy page:** renders the approved policy in `docs/privacy-policy.md` (approved by Luis 2026-10-08) word for word; it's indexed and in the sitemap. The text is in `privacy.*`: lists and tables are arrays (table rows of cells), read with `t.raw` for shape and `t.rich` per index. Rich tags: `b`, `code`, `email` (mailto from the tag's text) and one per provider link (`vercel`, `databricks`, `upstash`, `resend`, `turnstile`; URLs in the page). Apostrophes/quotes are typographic (’ “ ”), like the rest of the copy. Any policy change starts in `docs/privacy-policy.md` and needs Luis's approval. `check:messages` now compares arrays by index, so row and cell counts must match across locales.
- **Header links:** they point at `/{locale}#section`, not a bare `#section`, so they work from other pages too. On the home page they're still same-document jumps.
- **Email:** `react-email` 6 ships the components itself (`@react-email/components` is deprecated). `send-confirmation.ts` renders HTML + plain text and sends with Resend (which returns `{ error }`, not a throw), with an idempotency key from the token hash. Email clients can't read CSS vars, so `src/server/email/email-theme.ts` copies hex values from `brand/theme.css`: keep them in sync. The logo is HTML text (Gmail doesn't render SVG); swap in a PNG once one exists. `EMAIL_FROM` is the bare address and the optional `EMAIL_FROM_NAME` the display name (`formatFrom` joins them and normalizes whitespace). A combined `Name <addr>` value in Vercel was rejected by Resend as an invalid `from`, likely from a hidden character; the bare address worked. Without `RESEND_API_KEY`/`EMAIL_FROM`, dev logs the confirm link and production throws.
- **Confirm flow:** like unsubscribe, opening `/[locale]/confirm?token=…` changes nothing: the page does a read-only check (`checkConfirmToken`) and shows a "Confirm my email" button (`email.heading`/`body`/`button` copy), or the success/invalid card directly when the link is already confirmed or unusable. The button's server action (`src/server/confirm-action.ts`) confirms and redirects to the static `/confirm/success` or `/confirm/invalid` (the language switcher drops the query string); on a DB error it goes back to the page with `error=1`. `Cache-Control: no-store` and `X-Robots-Tag: noindex` for `/:locale/confirm` are set in `next.config.ts` `headers()`. The confirm hash is **kept** after confirming (deliberate deviation from DESIGN.md §5.4, approved by Luis), so a second click still shows success. Unsubscribing clears it. `confirm.loading` Spanish is `[ES TODO]`.
- **Unsubscribe flow:** opening `/[locale]/unsubscribe?token=…` only shows a button (approved by Luis), so mail scanners can't unsubscribe anyone; the server action does the update and redirects to `/unsubscribe/done`. `/api/unsubscribe` takes RFC 8058 one-click POSTs from the `List-Unsubscribe` header, and redirects a GET to the page. The `unsubscribe.prompt*`/`invalid*`/`loading` Spanish strings are `[ES TODO]`.
- **Retention cron:** `vercel.json` runs `GET /api/cron/purge-pending` daily (06:00 UTC; any time in that hour on Hobby), authorized by `Authorization: Bearer $CRON_SECRET` (constant-time compare; unset secret = always 401). It deletes `pending` rows with `created_at` > 30 days old, but keeps rows whose confirm link is still valid (`confirm_sent_at` < 72h), because a re-signup keeps the old `created_at`. Logs the count. DESIGN.md §5.6. `CRON_SECRET` must be set in Vercel Production.
- **Social profiles:** the three URLs live in `src/lib/social.ts`. The footer shows them as icon-only links (glyphs in `icons.tsx`, solid `currentColor`) inside the footer `<nav>`. Their `-my-3 -mr-3` keeps the 44px hit areas from growing the footer and aligns the last glyph to the edge; the nav's `gap-y-3` must match, or a wrapped row's hit areas overlap the text links (the Spanish footer wraps at 360–390px). The locale layout emits Organization JSON-LD (`name`, `url`, absolute `/brand/icon.svg` logo, `sameAs` from the same constant), escaped per the Next JSON-LD guide.
- **Status pages:** `src/components/status-page.tsx` holds the shared shell (header, centered card, footer) and `statusPageMetadata` (`noindex, nofollow`).
- **Share images:** `src/app/[locale]/opengraph-image.tsx` uses `generateImageMetadata` (one id, `card`) so the alt text can be translated; URLs are `/{locale}/opengraph-image/card`. Satori needs static TTFs (no woff2, no variable fonts): they're in `assets/fonts/` with their OFL licenses. Satori has no inline layout, so the headline is one flex item per word. Hex values are copied from `brand/theme.css` (keep in sync), and `MarkPaths` in `logo.tsx` takes explicit colors for it. Images render on first request, then cache.
- **Sync file reads in metadata routes:** under `cacheComponents`, async `fs` calls stop prerendering (the OG image then 500s at runtime). `opengraph-image.tsx` and `apple-icon.tsx` use `readFileSync`.
- **Fonts:** Newsreader is self-hosted via `next/font/local` (`assets/fonts/Newsreader-*.latin.woff2`): three faces at fixed weights with the opsz axis kept, ~180 KB against ~280 KB for Google's full variable files. The download URL pattern is in `fonts.ts`. Figtree and Inter stay on `next/font/google`. (DESIGN.md §3.2 says `next/font/google`; this is a deliberate deviation for performance.)
- **Analytics:** `<Analytics />` from `@vercel/analytics/next` in the locale layout; `waitlist_submit` with `{ locale, source }` fires when the server answers success. Web Analytics must be enabled in the Vercel project (custom events need a Pro plan). Locally the script 404s, which costs Lighthouse best-practices 4 points; ignore it off Vercel.
- **Lighthouse (local prod build, simulated mobile):** `/en` 86–87 performance, `/privacy` 89; desktop 99–100; accessibility and SEO 100; best practices 96 (only the local analytics 404). The rest of mobile LCP is framework JS plus fonts; recheck on a Vercel preview with PageSpeed Insights. Lighthouse's unscored `label-content-name-mismatch` flags the language links (visible "EN", `aria-label` "English", as DESIGN.md §6.3 specifies).
- **Open questions for Luis:** the unused `switcher.switchTo` key; a translated 404 page, which needs copy that doesn't exist yet; the Spanish text for `nav.primaryLabel` / `footer.navLabel`, `confirm.loading` and the new `unsubscribe.*` strings (currently `[ES TODO]`); a PNG logo for the email.

## Commands
npm, Node 24.
- `npm run dev`: dev server (Turbopack) at http://localhost:3000
- `npm run build` / `npm start`: production build and serve
- `npm run lint`: ESLint (flat config, Next core-web-vitals + TypeScript + Prettier)
- `npm run typecheck`: `next typegen && tsc --noEmit`. If it reports errors in `.next/dev/types` after routes move, delete `.next` and rerun.
- `npm run check:messages`: fails if `messages/en.json` and `messages/es.json` keys differ
- `npm run format` / `npm run format:check`: Prettier with Tailwind class sorting. `brand/`, `docs/`, `CLAUDE.md` and `AGENTS.md` are excluded and keep their authored formatting.
- `npm test`: Vitest unit tests (`src/**/*.test.ts`). `server-only` is aliased to an empty module in `vitest.config.mts`.
- `npm run db:generate` / `npm run db:migrate`: drizzle-kit, for local dev against the Neon dev branch. Migrations live in `drizzle/`, and the config loads `.env.local` for `DATABASE_URL`. Never `drizzle-kit push` against a shared database.
- `vercel-build` (Vercel runs it instead of `build`): `node scripts/migrate.mts && next build`. The script applies migrations only when `VERCEL_ENV` is production or preview, over `DATABASE_URL_UNPOOLED` (falling back to `DATABASE_URL`). Migrations must be backward-compatible with the deployed code (expand → deploy → contract; DESIGN.md §5.5).
